# @goturbo/addon

## 0.1.0-beta.0

### Minor Changes

- [#45](https://github.com/asibilia/range-finder--classic/pull/45) [`8ae6142`](https://github.com/asibilia/range-finder--classic/commit/8ae6142e9e4657af5a9f87471debf5b00a297a5c) Thanks [@asibilia](https://github.com/asibilia)! - `/turbo macros` (or `/tb macros`) makes a per-character attack macro for each shock, Lightning Bolt and Chain Lightning you know, which starts auto-attack and casts the top rank, and swaps it onto your action bars wherever that spell sits, at any rank ([#44](https://github.com/asibilia/range-finder--classic/issues/44)).

- [#43](https://github.com/asibilia/range-finder--classic/pull/43) [`a7ac242`](https://github.com/asibilia/range-finder--classic/commit/a7ac242af7e81f2215bbad4aae01ae3ce9425ad6) Thanks [@asibilia](https://github.com/asibilia)! - Turbo v1, the Enhancement Shaman HUD for WoW: Forever ([#27](https://github.com/asibilia/range-finder--classic/issues/27)–[#36](https://github.com/asibilia/range-finder--classic/issues/36)). Turbo loads only on Forever (interface 16001) and explains why on any other client; other classes get a one-time "Turbo doesn't support <Class> yet". Shamans get one compact HUD card that fades in while engaged, can be moved with Edit Mode and has an "always show" option. The card shows the range band (Melee, Shock range, Bolt range, Out of range), a main-hand swing timer with an adjustable safe window that greys during hard casts and dims out of range, four totem slots with countdown numbers, a swirl, a pulse near expiry and a red flash on early death, the weapon imbue with time left, Lightning Shield charges, the shared shock cooldown and Stormstrike, Maelstrom Weapon pips (off until readable in combat) and a mana bar that turns red under 20%. Silent, glowing reminders flag a missing or expiring imbue or Lightning Shield, even when the card is hidden, and stay quiet while resting, mounted or on a flight path. Settings live on a Turbo page in Options → AddOns and in `TurboDB`, split by class; `/turbo` and `/tb` print help and toggle modules and "always show", and `/turbo debug` logs which values are readable or secret. Turbo never reads a secret value and never changes the player's CVars or Blizzard frames.

### Patch Changes

- [#42](https://github.com/asibilia/range-finder--classic/pull/42) [`ad5b49a`](https://github.com/asibilia/range-finder--classic/commit/ad5b49ab75fbf182ece551e4e1afd726b75bc3db) Thanks [@asibilia](https://github.com/asibilia)! - Lua toolchain and the fake-game test seam ([#26](https://github.com/asibilia/range-finder--classic/issues/26)). `bun run check` now runs everything CI runs: type-check, lint and syncpack, then the Lua checks (`bun run lua:all`): StyLua's format check, LuaLS headless with the pinned WoW annotations plus an in-repo stub file for Forever-only APIs (the swing events and `C_SwingTimer`, `C_Item.GetWeaponEnchantInfo`, the new duration-object methods, and the aura container), the secret-read guard, and the tests. `bun run tools:fetch` downloads LuaLS, the annotations and Forever's API docs into the gitignored `.tools/`, and CI caches them. `bun test` runs real Lua 5.1 in WebAssembly against a fake game that replaces the safe layer: scripted events and readings, a clock the test moves, secret stand-ins that fail loudly when read, compared, used in math, concatenated, stringified or kept as a table key, and a recorder of every widget call and frame change. The guard reads Forever's API docs and fails any secret-returning game call outside `Turbo/core/safe-layer.lua`; a deliberately violating fixture proves it. The addon folder starts with the safe layer, which offers the same contract as the fake.

- [#42](https://github.com/asibilia/range-finder--classic/pull/42) [`ad5b49a`](https://github.com/asibilia/range-finder--classic/commit/ad5b49ab75fbf182ece551e4e1afd726b75bc3db) Thanks [@asibilia](https://github.com/asibilia)! - Reboot the repo as Turbo's Bun monorepo ([#24](https://github.com/asibilia/range-finder--classic/issues/24)). The 2023 RangeFinder Classic addon, its packaging config, binary lockfile, tsconfig, changesets and `dev-tools` release scripts are gone from `main`; the code is kept under the tag `legacy/rangefinder-classic-v0.2.0`. The repo now has Bun workspaces with `@goturbo/addon` and `@goturbo/web`, a text lockfile, TMNB's supply-chain install settings, ESLint 9 + Prettier, per-package tsconfig, the conventional-commit helper, changesets (required on PRs) and syncpack with a version catalog. CI runs lint, type-check and syncpack on pull requests and `main`. The glossary, the MuninnDB vault config, the agent guides and the probe (code only) are committed.

- [#43](https://github.com/asibilia/range-finder--classic/pull/43) [`a7ac242`](https://github.com/asibilia/range-finder--classic/commit/a7ac242af7e81f2215bbad4aae01ae3ce9425ad6) Thanks [@asibilia](https://github.com/asibilia)! - Release pipeline ([#37](https://github.com/asibilia/range-finder--classic/issues/37)) and the dev link. Changesets runs in beta pre-release mode with a Version PR workflow; merging it bumps the addon version and changelog, a workflow step tags `v<version>`, and the tag runs the BigWigs packager, which publishes the zip as a GitHub pre-release and uploads to CurseForge and Wago once their ids and tokens are set. The newest changelog entry becomes the release notes, and CI fails if the packaged zip holds anything outside the `Turbo` folder. `bun run dev:link` links the shipped addon folder into the beta client's AddOns folder, and `bun run dev:watch` is a copy-on-save watcher for clients that don't follow the link.
